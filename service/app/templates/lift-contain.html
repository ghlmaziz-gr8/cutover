Modernized template · first step

Run as is, in containers

Package the application as it is and run it in containers. Nothing about the code or the data changes, so the risk is low, and the team gets a repeatable way to run it while the rest is modernized.

When it fits

Cutover recommends this when the application has no infrastructure as code, has dependencies to upgrade, or the team needs a safe first step before larger changes.

No infrastructure as codeDependencies to upgradeLow risk

How the move goes

  1. Confirm what runs. Use the runtime and dependency findings to choose a base image that matches the application.
  2. Write the container definition and keep it in the repository, next to the code.
  3. Move configuration out of the code into environment settings, so the same image runs in every place.
  4. Run it in a test environment and compare its behaviour with the current one.
  5. Move to production once the comparison is clean, and keep the old host for a fallback period.

What stays and what changes

Stays for now
  • The code, unchanged
  • The database and its data
  • The screens and roles
Changes
  • Where the application runs
  • How it is built and deployed
  • Configuration moves to settings

Main risks

  • Old components may not run on a current base image. Test each one.
  • Files written to the server's disk are lost when a container restarts. Find them first.
  • This moves the problem rather than solving it. Plan the next steps while it runs.

This is a template, not a plan for one application. It is a good first step when the other templates need more time.
